# Interop fixtures

The TypeScript and Go implementations of the wire protocol, Noise and the privilege payloads are written
independently. They are kept byte-compatible by golden vectors in `test/interop`: the TypeScript side
generates them, both sides consume them, and Go must decode what TypeScript encoded.

| Fixture | Contents | Generated by | TypeScript consumer | Go consumer |
|---|---|---|---|---|
| `cbor_core_golden_vectors.json` | The `CBOR-CORE-INT-v1` profile: RFC 8949 §4.2.1 encoding, map key order, integer-only, no tags/floats/indefinite lengths | Fixed vectors; edit only with the specification | `packages/protocol/test/cbor.test.ts` | `client/internal/protocol/cbor_test.go` |
| `crh_frames.json` | Positive and negative CRH frames: headers, command/response/event tuples, malformed inputs | `packages/protocol/test/generate-crh-frames.ts` | `crh_frames.test.ts` | `client/internal/protocol/fixture_test.go` |
| `noise-crh.json` | One Noise IK handshake as CRH uses it, including the `crh/<major>` prologue and the challenge | `packages/protocol/test/generate-noise-interop.ts` | `packages/noise/test/noise.test.ts` | `client/internal/noise/interop_test.go` |
| `m4_vectors.json` | Authorization payloads, `spec_sha256`, TrustSummary digests, crh-priv handshake and frames, SSHSIG and WebAuthn assertions | `packages/protocol/test/generate-m4-vectors.ts` (fresh keys each run; needs `ssh-keygen`) | `m4_vectors.test.ts` | `client/internal/protocol/m4_test.go`, `client/internal/privileged/authz/sshsig_test.go`, `client/internal/privileged/wire/wire_test.go` |
| `m4_authz_cases.json` | Shared authorization decisions: rule matching, prefix, env, groups, `task_ids`/attempt, time bounds, cosign, conservative fallbacks | `packages/protocol/test/generate-m4-authz-cases.ts` | `m4_authz_cases.test.ts` | `client/internal/privileged/authz/authz_test.go` |

## Regenerating

Run from the repository root:

```bash
node packages/protocol/test/generate-crh-frames.ts
node packages/protocol/test/generate-noise-interop.ts
node packages/protocol/test/generate-m4-vectors.ts
node packages/protocol/test/generate-m4-authz-cases.ts
```

Then run both sides:

```bash
pnpm --filter @crh/protocol test
pnpm test:go
```

Rules:

- **Never hand-edit a generated fixture.** Change the builder under `packages/protocol/test/` and regenerate.
- `m4_vectors.json` is built with fresh keys on every run, so regenerating it produces a large diff. That is
  expected; commit it only when the change is intended, and keep the Go and TypeScript suites green in the
  same change.
- The private keys in the generated fixtures are test material. They sign test payloads only.
- `cbor_core_golden_vectors.json` is the one fixture without a generator; it mirrors the profile rules, so a
  change there is a specification change and needs both implementations updated.

## Why these exist

The protocol is hand-written on both sides (no code generation). A change that only TypeScript accepts is
still a protocol bug if Go disagrees. The fixtures turn that into an ordinary test failure on either side,
without needing both processes to run together. The end-to-end suites in `server/test/e2e` and
`server/test/system/privileged` then check the same bytes through a real `crha`.

The `m4_` prefix on two fixtures is a development-time name. They will be renamed once the pre-1.0 protocol
version reset removes the remaining prototype identifiers; until then, the names are stable and both sides
reference them directly.
