# Testing

This directory is the single entry point for how ClusterRightHand is tested: what each layer starts,
how to run it, and what CI covers. The suites are organised by what they exercise and what they need.

## Test layers

| Layer | Suite | Runner | What actually runs | Time | In CI |
|---|---|---|---|---|---|
| L1 unit and integration | `server/test/*.test.ts`, `packages/*/test`, `web/src/**/*.test.{ts,tsx}` | Vitest | Everything in-process. SQLite `:memory:` by default; PostgreSQL and a live sshd only when their variables are set. | seconds | yes |
| L2 interop vectors | `test/interop/*.json` | Vitest and `go test` | Fixtures generated by the TypeScript code, decoded independently by the Go code. | seconds | yes |
| L3 server e2e | `server/test/e2e` | Vitest | An in-process crhs plus a real `crha` binary and pi's faux model. The crash suite spawns a real crhs process so it can be killed. | about 1 minute | yes |
| L4 privileged system | `server/test/system/privileged` | Vitest and podman | One container per node: a real `crha privileged run` as root, a real `crha run` as uid 998, real sudo and doas, and a real sshd. | about 1 minute after the image exists | no |
| L5 WebUI e2e | `web/e2e` | Playwright on Chromium | A real crhs (in-process) serving the built `web/dist`, a real crha node and the faux model. | about 30 seconds | yes |
| L6 WebUI mock | `web/e2e-mock` | Playwright on Chromium | The built WebUI against a mocked API, served by `vite preview`. | seconds per spec | no |
| L7 Go | `client/**/*_test.go` | `go test` | Pure Go units and integration points. | about 15 seconds | yes |
| L8 performance | `server/test/perf`, `web/e2e-mock/perf` | Vitest, Playwright | The faux model on real SQLite storage; the WebUI under CPU throttling. | minutes | no |

L4 is described in [Privileged system tests](privileged.md), the server layers in
[Server tests](server.md), the WebUI layers in [WebUI tests](web.md), and the shared fixtures in
[Interop fixtures](interop.md).

## What to run when

| You changed | At least run |
|---|---|
| Anything, before pushing | `pnpm check` |
| Protocol, Noise, frames | `pnpm --filter @crh/protocol test && pnpm test:go` |
| Storage, migrations, schema | `pnpm --filter @crh/server test` (add `CRH_TEST_PG_URL` for PostgreSQL) |
| Cluster core, tasks, SSH transport, batch output | `pnpm --filter @crh/server test && pnpm test:e2e` |
| Privilege, authorization, the privileged daemon | `pnpm --filter @crh/server test`, `pnpm test:e2e`, `CRH_TEST_PODMAN=1 pnpm test:system` |
| Agent runtime, sessions, subagents, quota | `pnpm --filter @crh/server test && pnpm test:e2e` |
| WebUI | `pnpm --filter @crh/web test && pnpm test:ui && pnpm --filter @crh/web test:ui:mock` |
| Go client only | `pnpm test:go` |
| Before a release | Everything above, plus `pnpm --filter @crh/server test:perf` and `pnpm --filter @crh/web test:perf`, then a manual pass over a demo cluster |

## Commands

From the repository root:

```bash
pnpm check                  # Biome, type checks, gofmt and go vet
pnpm test                   # every package's test script plus go test
pnpm test:e2e               # server/test/e2e
CRH_TEST_PODMAN=1 pnpm test:system   # server/test/system/privileged
pnpm test:ui                # WebUI Playwright against a real backend
pnpm test:go                # go test ./...
```

Package-level commands, for the suites that are not aliased at the root:

```bash
pnpm --filter @crh/server test          # L1, excludes e2e, perf and system
pnpm --filter @crh/server test:e2e      # L3
pnpm --filter @crh/server test:system   # L4
pnpm --filter @crh/server test:perf     # L8 server
pnpm --filter @crh/protocol test        # L1 protocol and L2 fixtures
pnpm --filter @crh/noise test           # L1 Noise
pnpm --filter @crh/web test             # Vitest plus i18n:check
pnpm --filter @crh/web test:ui          # L5
pnpm --filter @crh/web test:ui:mock     # L6
pnpm --filter @crh/web test:perf        # L8 WebUI
```

There is no root alias for the mock or performance suites. Neither they nor the e2e and system
suites are part of `pnpm test`.

A single file or test:

```bash
pnpm --filter @crh/server exec vitest run test/scheduler.test.ts
pnpm --filter @crh/server exec vitest run test/e2e/crash.e2e.test.ts
CRH_TEST_PODMAN=1 pnpm --filter @crh/server exec vitest run test/system/privileged/forward.test.ts
pnpm --filter @crh/web exec playwright test e2e/sessions.spec.ts
pnpm --filter @crh/web exec playwright test --config e2e-mock/playwright.config.ts e2e-mock/session-list.spec.ts
cd client && GOCACHE=/tmp/crh-go-cache go test ./internal/transport/...
```

## Prerequisites

| Tool | Needed by | Notes |
|---|---|---|
| Node.js ≥ 24.7 and pnpm 12 | everything TypeScript | Node runs `.ts` directly; there is no build step for the server |
| Go (version from `client/go.mod`) | L3, L7, L4 image build | The e2e suites build a static `crha` |
| Chromium | L5, L6, L8 WebUI | `pnpm --filter @crh/web exec playwright install chromium` |
| Rootless podman | L4 | Linux; `--network=host` and fixed uid 998 are assumed |
| PostgreSQL 17 | L1 PostgreSQL variant | Any reachable server; the URL goes into `CRH_TEST_PG_URL` |
| An sshd and a key | SSH integration tests, L5 SSH wizard | `CRH_TEST_SSH` and `CRH_TEST_SSH_KEY`; the wizard needs only `CRH_TEST_SSH_JUMP` |

The test services are not started automatically. PostgreSQL and SSH are expected to exist already;
the privileged suite builds its own container image and is self-contained. The containers used during
development (`crh-test-pg`, `crh-test-jump`, `crh-test-target`) are not part of the repository and
are not required.

Example PostgreSQL container:

```bash
podman run -d --name crh-test-pg \
  -e POSTGRES_USER=crh -e POSTGRES_PASSWORD=crh -e POSTGRES_DB=crh_test \
  -p 127.0.0.1:55432:5432 docker.io/library/postgres:17
CRH_TEST_PG_URL=postgres://crh:crh@127.0.0.1:55432/crh_test pnpm --filter @crh/server test
```

## Environment variables

| Variable | Effect when set | Effect when unset |
|---|---|---|
| `CRH_TEST_PG_URL` | Enables every PostgreSQL variant: the `describeBackends` suites, the `PgStorage` conformance suite, and the PostgreSQL-only search and retention checks. Each test database gets its own schema; DDL is serialised with an advisory lock. | PostgreSQL variants are skipped and counted as skipped. |
| `CRH_TEST_SSH` | `user@host:port` of a live sshd for `ssh-route` and `ssh-file-task`. | Those suites are skipped. |
| `CRH_TEST_SSH_KEY` | Path to the private key for `CRH_TEST_SSH`. | The same skip. |
| `CRH_TEST_SSH_JUMP` | `host:port` of an sshd whose host key can be probed; enables the WebUI SSH wizard spec. | That spec is skipped. |
| `CRH_TEST_PODMAN=1` | Enables the privileged system suite. | The whole suite is skipped. |
| `CRH_PODMAN` | Path or name of the podman binary. | Defaults to `podman`. |
| `CRH_CHROMIUM` | Path to a system Chromium for the real-backend Playwright suite. | Playwright's downloaded browser is used. |
| `CRH_SHOT_DIR` | Output directory for the session review screenshots. | `web/e2e-mock/review/session-shots`. |
| `PERF_RUNS` | Number of repetitions per WebUI performance metric. | 3. |
| `PERF_STREAM_SCALE` | Scales the streamed characters in the WebUI performance test, for a quick smoke run. | 1 (the full stream). |
| `GOCACHE` | Go build cache. Set it when the default cache is read-only. | Go's default cache. |

## CI

`.github/workflows/ci.yml` runs on pushes to `main` and on pull requests, in order:

1. `pnpm check`
2. `pnpm test`, with a PostgreSQL 17 service and `CRH_TEST_PG_URL` set
3. `pnpm --filter @crh/web build`
4. `pnpm test:e2e`
5. `pnpm test:ui`, after installing Chromium

Known gaps, kept here so they are deliberate rather than forgotten:

- L4 (`test:system`) is not in CI: it needs rootless podman and is Linux-only.
- SSH integration (`CRH_TEST_SSH`) is not in CI: it needs an sshd service.
- L6 and L8 are not in CI: they are slower and, for the performance suites, machine-dependent.
- `go test` runs without `-race`.
- Playwright runs Chromium only.

## Conventions

- Name tests after the behaviour. The capability-to-test mapping belongs in the testing document for
  that layer, not in a test name.
- A conditional skip states its reason in the skip message. Suites that need an external service are
  gated by the environment variables above; suites that need a local binary check it first
  (`goAvailable`, `podmanAvailable`) and skip without it.
- Tests do not depend on the network, the wall clock, or the order of other test files.
- Every test that creates temporary directories or child processes cleans them up in
  `afterAll` or `finally`.
- Golden vectors in `test/interop` are generated, never hand-edited; see
  [Interop fixtures](interop.md).
- A test that drives the agent runtime through the faux model accounts for title generation: a
  session created without a title consumes one model response for its title at the end of the first
  run, so the test titles the session or queues the extra response.
- Do not assert on log wording unless the wording is part of the contract.

## Troubleshooting

**`go vet` or `go test` fails with "read-only file system" under `~/.cache/go-build`.** The sandbox
has a read-only home cache. Set `GOCACHE` to a writable directory, for example
`GOCACHE=/tmp/crh-go-cache`.

**`podman` fails with "set sticky bit on: chmod /run/user/1000/libpod: read-only file system".** The
sandbox cannot run rootless podman. Run `test:system` outside it; `podmanAvailable` turns the suite
into a clean skip when `podman` cannot answer.

**PostgreSQL tests fail with `duplicate key value violates unique constraint "audit_events_pkey"`.**
Two test files migrated or wrote into the same schema. The helpers give every test database its own
schema and take an advisory lock for DDL; a stray run against a shared database is the usual cause.

**The e2e suite fails before any test runs.** It builds a `crha` binary and needs Go on `PATH`. The
WebUI suite also builds `web/dist` in its `globalSetup`; a stale `dist` is not reused.

**A leftover `crha`, `sleep` or podman container is in the way.** The harness kills children in
`afterAll` and `pkill`s known command lines, but a killed test process can leave one behind. Remove
containers with `podman rm -f`, and check `pgrep -af crha`.
