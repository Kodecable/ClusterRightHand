# M4 提权：实现计划

本文记录 M4 已确定的范围和实现顺序。协议层（含授权 payload）见
[execution-plane.md](execution-plane.md) 的 M3.5；信任配置的语义见 [privilege.md](privilege.md)。

## 已确定的决策

1. **信任缓存**：crhs 在 `nodes` 中缓存 crha 特权模式上报的 `TrustSummary`、digest 和两种模式的运行身份。
   - 节点连接时查询一次；
   - crha 配置变化（reload）时主动推送；
   - 收到后更新数据库并审计；
   - 任务授权时记录使用的 digest；等待期间 digest 变化就重新计算。
2. **crhs 计算授权方案**：不再依赖 `Preflight` 请求。crhs 用 RE2（Node 包 `re2`）按信任项的规则计算候选路径，但 crha 特权模式执行前仍会完整复验；crhs 的判断只决定走哪条路，不构成最终放行。
3. **只考虑会话所有者**：特权任务只为 `on_behalf_of_user_id` 计算 user 信任项和凭据。共享用户、其他管理员不参与；共享会话仍以所有者身份行事。
4. **授权与联署是同一对象上的多个签名**：
   - 一个 payload，`signatures[]`；
   - 用户签名和 crhs 联署签同一份 CBOR payload；
   - `require-cosign` 要求同一 payload 上同时有合格 user 签名和 `role=crhs` 的 cosign；
   - 授权 id 仍是 payload 的 SHA-256；吊销一次吊销整个对象；
   - payload 带 `attempt`，同一 task id 的每次重试都换新授权。
5. **SSH 不参与提权**：
   - SSH 节点使用 `ignore` 语义：`privileged` 标志被忽略，任务以 SSH 用户执行；
   - 任务输出中明确提示这次没有提权；
   - 保留现有 SFTP `file.*` 任务，不因 M4 删除；
   - 没有 `forward` / `native` / `Preflight` / 信任配置。
6. **WebUI 导出 trust 片段**：节点信任摘要页面可以导出可直接粘贴进 `privileged.toml` 的 `[[trust]]` 片段（crhs 公钥、指纹、kinds、规则、TTL 等）。
7. **native/ignore/reject 只属于 crha 节点**；SSH 是 ignore 的特例。
8. **任务重试与部分成功**：
   - 同一 task id 最多 accepted/executed 一次；
   - crha 在 `task.accepted` 前明确拒绝授权时，任务回到 `awaiting_authorization`，用 `attempt + 1` 重试；
   - 部分节点通过、部分拒绝时任务独立，不回滚已执行任务；`fail_fast` 只影响未启动节点；
   - 授权等待不自动超时。
9. **批量执行输出**由 M3.5/执行平面实现：默认只返回状态，完整输出留在节点；可选文本模式每节点保留尾部 8KB/128 行，所有节点共享单任务总预算，按输出到达顺序丢弃；丢弃也 ack，不优先保留失败节点。SSH 不保留完整输出。见 [execution-plane.md](execution-plane.md#输出)。

## 架构

```
crhs 策略 / Auto Review
        │
        ├── SSH 节点：ignore，加输出提示
        │
        └── crha 节点
              ├── native / ignore：不需要 crha 授权
              └── forward
                    │ TrustSummary（缓存 + 变化推送）
                    ▼
                  crhs 从缓存计算授权方案
                    ├── crhs execute：签 exact + task_id + 短 deadline
                    ├── 所有者 user：等待签名（Passkey / crha grant）
                    ├── local：等待 crha approve
                    └── 无路径：拒绝并说明
                          │
                          ▼
                  crha 非特权模式 forward
                          │ unix socket + SO_PEERCRED
                          ▼
                  crha 特权模式
                    ├── 验证 payload/signatures/trust/吊销/used
                    ├── 规则、路径、env、spec hash
                    └── 以自身身份执行
```

## 任务与数据

- `tasks.authorization`：授权状态、方案、payload id、attempt、trust digest、拒绝原因。
- 新增任务状态 `awaiting_authorization`：策略已通过、等待用户/本地签名；与 `awaiting_approval` 分开。
- `authorizations`：一个 payload 一行，`signatures` 为 JSON 数组；payload 带 attempt；`revoked_at` 用于吊销。
- `nodes.trust_summary` / `nodes.trust_digest` / `nodes.run_identities`。
- `user_credentials`：所有者的 SSH key / WebAuthn 凭据。
- `secrets`：`authorization_signing_key` 由 crhs 生成/加载；支持导出，后续支持 ssh-agent。
- `task_groups`：第一阶段只做单任务特权；群组特权任务后置，避免按节点收集签名的复杂度。

## 阶段

### M4.1 crha 特权模式（独立可用）

- `privileged.toml` 解析和校验（trust、groups、uid、clock_skew）。
- unix socket + `SO_PEERCRED`。
- 授权校验：trust、nodes/groups、时间、max_ttl、require_exact、exact/prefix、spec hash、env、allow/deny、cosign、吊销、used。
- 特权执行：exec 和 file.*；路径绝对、clean、无符号链接（`openat2(RESOLVE_NO_SYMLINKS)`）；cwd `/`；env 白名单；进程组；超时。
- used/revoked 持久化、本地日志、`crha pending/approve/privileged revoke`、`crha privileged run`。

**验收**：不经过 crhs，直接向 socket 发一条签名任务可执行；重放、过期、吊销、错 task id、符号链接全部拒绝。

### M4.2 crhs 信任缓存 + forward

- crhs 生成/加载授权签名密钥。
- TrustQuery/TrustSummary 推送/缓存/digest 审计。
- 从缓存计算所有者的授权方案；RE2 匹配；crhs 是预演，crha 拒绝后回退到 owner 的 user/local 路径。
- `awaiting_authorization` 状态、attempt 和签名下发。
- crha 非特权模式 `forward` 转发。
- WebUI 信任摘要 + 导出 trust 片段。
- 先 exec，再 file。

**验收**：信任 crhs execute 的节点能跑特权任务；节点只信任 user、不信任 crhs 时，crhs 无法单独提权。

### M4.3 用户控制路径

- `crha grant`：用本地 SSH key/agent 签同一 CBOR payload。
- WebAuthn 所有者注册/签名。
- `crha approve` 本地批准。
- 联署（同一对象第二个签名）。
- 吊销推送和审计。

**验收**：只信任 user 的节点，crhs 单独执行失败；用户签名后成功；要求联署时缺任一个签名失败。

### M4.4 native/ignore/reject + SSH

- crha `native`（sudo/doas/run0，非交互）和 `ignore`/`reject`。
- SSH：ignore + 输出提示；保留 SFTP file 任务。
- `crha upgrade --apply`、trust reload、时钟偏差。
- 群组特权任务（如果前三个阶段未做）。
- M4 完成矩阵。

## 测试矩阵

纯 Go/TS 单测：

- CBOR payload、SSHSIG 与 `ssh-keygen` 互验、RE2 匹配。
- trust config 解析、授权校验矩阵。
- used/revoked 持久化、路径安全。
- 批量输出预算和内存上限。

podman e2e（文档在 `server/test/m4/README.md`，默认跳过，`CRH_TEST_PODMAN=1` 启用）：

1. `forward` + crhs execute：exec/file 成功。
2. `forward` 只信任 user：crhs 拒绝；用户签名后成功。
3. `require-cosign`。
4. `local`：`crha approve`。
5. `native` / `ignore` / `reject`。
6. 吊销、一次性授权重放、used 持久化、重启。
7. 符号链接、env、prefix 绕过。
8. SSH ignore + 输出提示；SFTP file 任务仍可用。
9. TrustSummary 变化和缓存失效。
10. 批量 status/text 输出。

## 完成标志

同一节点分别配置为：

- 信任服务端：crhs 可以按信任项执行特权任务；
- 只信任用户：crhs 无法单独提权，用户签名（可要求联署）后才能执行。

两条路径都有自动化测试；SSH 节点不参与提权，但普通 exec 和 SFTP file 任务保持可用。
